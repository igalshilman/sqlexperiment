# The patched TypeScript SDK

The Restate integration needs SDK changes that are not released: an
invocation that does not replay its journal, and a few fixes (see
[the requirements](../../../README.md#requirements)). This package holds those
changes to the TypeScript SDK; the shared core's, which it compiles to
WebAssembly, are in [`../sdk-shared-core`](../../../core/sdk-shared-core/README.md).

How SQL in a virtual object works, and how to use it: [`SQL.md`](SQL.md).

## TypeScript

[`setup.sh`](setup.sh) (`make sdk-ts`) clones both repositories at the
pinned revisions into `.build/` (ignored), applies
[`patches/`](patches) and [the shared core's patch](../../../core/sdk-shared-core/sdk-shared-core.patch), builds the shared core to
WebAssembly, inlines it into the SDK, and packs the SDK as
`.build/restatedev-restate-sdk-1.17.3.tgz`, which the pnpm
workspace installs wherever `@restatedev/restate-sdk` is used (an override in
[`pnpm-workspace.yaml`](../../pnpm-workspace.yaml)). It needs cargo with the
`wasm32-unknown-unknown` target, `wasm-bindgen` 0.2.121, node and pnpm. After
editing the clones, [`patches/regenerate.sh`](patches/regenerate.sh)
writes the patches back.

The shared core's tests pass with the patch (280), and so do the TypeScript
SDK's (66, of which 19 are the selector's, against a fake VM and the
published single-waiter progress channel, 6 the classification of SQL errors
and 3 the end of an attempt in a session), and its type tests
(`test/sql_context.test-d.ts`, checked by `tsc`).
